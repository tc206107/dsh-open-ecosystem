# 解决合并冲突

按以下五步解决进行中的 git merge / rebase 冲突，全程不放弃、不绕行。

## 第一步：看当前状态

先看清 merge / rebase 进行到了哪一步。检查 git 历史、冲突中的文件列表，以及当前处于合并还是变基状态。

## 第二步：找一手来源

对每一处冲突，找到它的一手来源，深入理解每一处改动为何发生、原始意图是什么。阅读提交信息、相关 PR、原始 issue / 工单。只有理解了双方意图，后续 hunk 取舍才有依据。

## 第三步：按意图逐 hunk 解决

逐个解决每个 hunk：

- 能同时保留双方意图时，同时保留。
- 相互冲突时，选择符合本次合并既定目标的那一方，并把取舍记录下来。
- 绝不发明新行为。
- 永远走完解决流程，绝不 `--abort`。

## 第四步：跑自动化检查

找出项目自带的自动化检查并运行，通常顺序是 typecheck → 测试 → 格式化。修复合并引入的任何破坏。

## 第五步：完成合并

暂存所有改动并提交。如果是 rebase，则继续 rebase 流程，直到所有提交都完成变基。

## 完成标准

- 已查看 git 历史与冲突文件，明确处于 merge 或 rebase 状态。
- 每处冲突都能说出改动双方的一手来源与原始意图。
- 每个 hunk 已按意图解决，没有引入自作的新行为，也没有使用 `--abort`。
- 项目的 typecheck → 测试 → 格式化等自动化检查已运行并通过。
- 所有改动已暂存并提交；rebase 场景下全部提交已完成变基。
