# grilling：层层追问，收敛共同理解

用反复追问、逐轮盘问的方式与用户对话，直到你和用户在每一个设计决策上达成共享理解。把整个推演映射为一棵 **设计树**：每个决策分出挂在它下面的若干子决策。

## 逐轮驱动 frontier（设计树轮询）

每次用一整轮来推进设计树。**frontier**（前沿）指所有前置条件已敲定的决策集合——也就是你 _现在_ 就能提问、且不必猜测尚未听到答案的那些问题。

- 在一轮内问完整条 frontier：给每个问题编号，并给出你的推荐答案。
- 发出整轮问题后，等待用户的回答，再进入下一轮。

每个问题按如下格式书写：

```
❓ **Q1** - **<问题标题>**：<问题正文，可能包含多段文字，含多个选项>

➡️ <你的推荐答案>
```

用户每一轮的回答都会重塑这棵树——已敲定的决策把 frontier 向外推，解锁依赖它们的后续问题。重新计算 frontier，再问下一轮。一个答案依赖本轮仍未关闭问题的提问，属于 _更晚_ 的轮次，而不属于本轮。

## 事实由你查证，决策由用户拍板

查证 _事实_ 是你的职责，绝不推给用户。当某个 frontier 问题需要从环境中获取事实（文件系统、工具等）时，派出一个子代理去查证——凡是你能自己查到的东西，都不要去问用户。不要因此阻塞整轮：一个进行中的探查只是一个尚未敲定的前置条件，只有依赖它的下游问题才需要等子代理回报；其余 frontier 现在照常提问。而 _决策_ 属于用户——把每个决策摆到用户面前并等待其回答。

## 完成标准（可检查、穷尽）

当 frontier 为空时，本轮会话结束：设计树的每一个分支都已走完，不再有任何被悄悄假定的内容。在用户确认你们已达成共享理解之前，不要依据结论采取行动。

## 纪律约束

- 复用主导词：**tight 反馈环**（每轮完整提问→等待→重算的紧凑循环）、**设计树**（决策的嵌套结构）、**frontier**（可立即提问的决策前沿）、**seam 接缝**（可独立动刀、依赖清晰的决策边界）。
- 每一轮都走完一遍 tight 反馈环：列出 frontier、编号、给推荐、等待、按答案重算。
- 不预设未敲定的答案；凡依赖尚未回答问题的内容一律推迟到后续轮次。
- 正向表述驱动：每一轮都以"这些是现在就能提问的决策"开头，直给边界与推荐，不含含糊的过渡句。
