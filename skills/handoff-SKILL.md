把当前会话总结成一份交接文档，让一个全新的智能体能够接手并继续推进工作。保存到用户操作系统的临时目录，而不是当前工作区。

完成标准：
- 文档已写入系统临时目录，并回报了完整文件路径。
- 接手者只凭这份文档即可理解上下文、复现状态并知道下一步做什么。

文档中必须包含以下小节：

1. 当前状态
   用一段话说明工作进展到哪一步：已完成什么、正在做什么、下一步是什么。

2. 交接要点
   - 待办与下一步：逐条列出尚未完成的具体动作，每条都可独立开始。
   - 关键决策与理由：记录影响后续方向的取舍及其原因。
   - 已知阻塞与风险：列出真实阻塞点、未决问题、潜在坑。
   - 关键文件与路径：列出接手需要读或改的文件，用路径或 URL 引用，不复制内容。

3. 建议技能（suggested skills）
   列出接手者应当启动的技能，用「运行 /技能名 skill」的散文式表述逐条建议，并说明每条建议本任务里的用途。

写作纪律：
- 只写本会话产生的、别处没有的新信息；已经落在规格、计划、ADR、issue、commit、diff 等其他产物里的内容不重复抄录，用路径或 URL 指向它们。
- 脱敏：凡涉及 API 密钥、密码、个人身份信息（PII）的一律以 <PLACEHOLDER> 占位，绝不写出真实值。
- 复用了「交接要点」这一主导词贯穿全文；建议技能章节用「运行 /xxx skill」统一表述，形成 tight 反馈环：接手者看完文档即可直接调用技能续作。
- 全文用简体中文。
